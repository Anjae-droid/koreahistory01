# 05. 웹앱 — 작업 규칙

한국사능력검정시험(심화) 기출을 회차별로 풀고, 문항 반응(A~D)과 오답 1줄 기록을 남겨
학습 코치 채팅에 붙여넣을 텍스트로 내보내는 로컬 웹앱.
"무엇을 왜" 는 `한능검웹앱_기획.md`, 사용법은 `README_한능검웹앱.md` 에 있다.

상위 `01. 프로그래밍/CLAUDE.md` 의 규칙을 그대로 따른다. 아래는 이 폴더에만 해당하는 규칙이다.

## 1. 폴더 역할

|경로|역할|수정|
|-|-|-|
|`src/template_round.html`|회차 풀이 화면 (디자인·기능 전부)|여기서만 고친다|
|`src/template_index.html`|회차 선택 화면|여기서만 고친다|
|`src/build.py`|`data/` → `dist/` 생성||
|`src/extract_pdf.py`|시험지 PDF → `data/<회차>/` (글자가 그림인 PDF 는 OCR, 공통 자료 자동 부착)||
|`src/import_explanations.py`|화면에서 작성한 해설(JSON)·해설 PDF → `문항.csv` 해설 칸||
|`src/era_keywords.py`|시대 자동 분류 키워드|분류가 틀리면 키워드만 조정|
|`data/rounds.csv`|회차, 시행일|사람이 편집 가능|
|`data/<회차>/문항.csv`|번호, 정답, 배점, 시대, 검토필요, 해설|사람이 엑셀로 편집 가능|
|`data/<회차>/img/qNN.jpg`|문항 이미지 (원본 PDF 에서만 추출)|교체만|
|`dist/`|생성물. 브라우저로 여는 곳|**절대 직접 수정 금지**|
|`inbox/`, `inbox/해설/`|새 PDF 투입구. 처리 후 `done/` 으로 이동||
|`_test/run_tests.py`|브라우저 회귀 테스트||
|`_archive/verN_<날짜>/`|구버전 보관||

## 2. 반드시 지킬 규칙

* 파일을 고치기 전에 `_archive/verN_<날짜>/` 에 먼저 복사한다. `data/` 의 CSV 도 포함.
* **지시하지 않은 것은 고치지 않는다.** 디자인 톤(베이지 배경·적갈색 헤더·둥근 카드)은
사용자가 한 번 되돌리라고 한 이력이 있다 (ver1 → ver2). 지시 없이 바꾸지 않는다.
* 디자인·기능 변경은 `src/template_*.html` 에서만 하고 `웹앱_빌드.bat` 으로 전 회차에 반영한다.
회차별 HTML 을 따로 고치지 않는다.
* 시각 요소(문항 이미지)는 공식 문제지 PDF 에서 추출한 것만 쓴다.
* CSV 는 UTF-8 with BOM (엑셀 한글 깨짐 방지).
* `.bat` 내용은 ASCII 만. 한글 경로는 배치파일에 쓰지 않고 Python 에서 처리한다.
* 결정론적 처리(자르기·정답 파싱·검증·빌드)는 Python. 비정형 판단(시대 분류 검토, 해설 작성)은 사람 또는 LLM.
* 외부 네트워크 호출·인증키 없음. `template_*.html` 에 `fetch` 를 넣지 않는다 (`file://` 에서 막힘).
데이터는 `<script src="data/...js">` 로 읽는다.
* 규칙·템플릿·빌드를 바꾼 뒤에는 `python _test\run_tests.py` 를 실행한다.
* 풀이 화면을 다시 그릴 때: 문항 이동은 `renderQuiz()`(맨 위로), 같은 문항 갱신(답·반응 선택)은 `renderQuiz(true)`(스크롤 유지). 헷갈리면 답을 고를 때마다 맨 위로 튀는 버그가 재발한다 (2026-09-30).

## 3. 학습 코치와 맞물린 부분 (바꾸면 코칭 방에도 알릴 것)

* 문항 반응 4분류: A 바로 맞음 / B 헷갈렸는데 맞음 / C 두 선지에서 틀림 / D 아예 모름.
정답이면 A·B, 오답·미응답이면 C·D 만 고를 수 있다.
* 1줄 기록 양식: `회차-번호 / 시대 / 내 답·정답 / 두 선지를 구분하는 근거` (D 는 정답 선지 핵심 키워드).
B·C·D 는 필수, A 는 선택.
* 연습 모드(반 회차)는 시간 기록 없음. 실전 모드만 80분 타이머.
* 결과 화면 "기록 복사" 텍스트 형식은 코치가 파싱하는 입력이다. 형식을 바꾸면 코칭 방에 알린다.

## 4. 알려진 한계

* 화면에서 작성한 해설은 localStorage(`hkh.exps.v1`)에 있다가 "해설 파일 받기 → 해설_추가.bat" 으로 `문항.csv` 에 반영된다.
  반영된 항목(문항.csv 해설과 같아진 것)은 화면을 열 때 자동으로 지운다.
* 기록은 브라우저 localStorage(`hkh.sessions.v1`)에만 저장된다. 기기·브라우저가 바뀌면 안 보인다.
홈 화면의 백업/불러오기로 옮긴다.
* 텍스트 레이어 없는 PDF(65~69·73·74·78·79회)는 OCR(Tesseract + kor)로 처리한다 (2026-09-30).
  Windows PC 에는 Tesseract 가 없으므로, 새 회차는 Cowork 에서 추출하거나 사용자가 Tesseract 를 설치해야 한다.
  OCR 은 문항 **번호 위치 찾기**와 **시대 분류용 텍스트**에만 쓴다. 이미지는 PDF 를 그대로 렌더링한다.
* **단 마지막 문항 아래쪽 잘림 (2026-09-30 수정)**: 쪽 번호 위치를 "홀짝 쪽 공통 잉크 행"으로 찾던 방식이
  본문 행까지 공통으로 잡아, OCR 9개 회차의 각 단 마지막 문항(약 210문항)이 아래 8% 정도 잘렸다(78회 2번 등).
  지금은 아래쪽의 폭 좁은 잉크 덩어리(쪽 번호 상자)를 찾아 그 위까지 자른다. 텍스트 회차도 다음 문항 번호
  bbox 위 여백 때문에 선지 마지막 줄이 1pt 잘리던 것(72회 6번)을 `-8 → -3` 으로 고쳤다.
  `_test/run_tests.py` 가 "이미지 맨 아래 2행에 글자가 닿는지" 로 재발을 검사한다.
* 77회 이미지는 원본 PDF 가 없어 옛 방식 그대로다(단 마지막 문항에 쪽 번호가 같이 찍혀 있음, 내용은 온전).
* 번호 위치는 "각 단 왼쪽 여백의 잉크 덩어리 + 숫자 OCR + 순서 검증"으로 찾는다. 레이아웃 2종
  (65~68회 748×1091pt, 69회 이후 729×1032pt) 모두 확인. 50개가 안 나오면 추출하지 않는다.
* `[NN~MM] 다음 자료를 읽고…` 공통 자료는 단의 첫 문항이 평소보다 아래에서 시작하면 찾아 붙인다
  (66회 30~31, 67·69·72회 47~48). 77회는 PDF 가 없어 확인하지 못했다.
* 시대 분류는 키워드 초안이다. `검토필요=Y` 문항은 사람이 확인한다.
  65~79 신규 9개 회차의 `검토필요` 172문항은 2026-09-30 LLM(Claude)이 OCR 텍스트로 검토해 확정했다.
  남은 Y: 69회 16번 (법화경 보탑도 — 고려로 두었으나 확인 필요).
  여러 시대를 묶는 문항(순서 나열·통사·지역사·문화유산 모음)은 `미분류`.
* 여운형 문항은 `해방이후` 로 통일 (66-44, 67-44, 68-47).
* `rounds.csv` 시행일은 2026-09-30 웹 확인 완료 (72회 정정). 새 회차는 추가할 때 확인한다.
* 시대 분류 기준: 후삼국(궁예·견훤·후고구려·태봉)은 **남북국** (2026-09-30 사용자 결정).
